## Fixture boundaries

The seed preserves 10 departments, 206 employee rows (192 active, 13 resigned,
1 long leave), one duplicate name across departments, nullable employee numbers,
shift/manager fields, and 7 manager references. Employee/manager names and every
seed UUID are synthetic; the private workbook fingerprint is replaced with a
synthetic fixture fingerprint. No passwords, authentication accounts, real HR
exceptions or private employee source files are included.

The seed requires the database session setting `hr.test_fixture = 'on'` and
refuses databases containing employees or authentication accounts. Existing
database/export test setup enables this only inside disposable PGlite instances.
These are guardrails, not permission to apply test data to a production database.

The baseline database test now explicitly describes synthetic fixture coverage
and searches the synthetic duplicate name. It no longer claims to verify the
private workbook or embeds its real duplicate employee name.

## Local configuration

The existing `vite.config.ts` reads only `d1` and `r2` from hosting configuration;
the build plugin copies it into the local build artifact. Neither needs the
private project identifier for local verification. No replacement identifier,
new Site, database binding or credential has been invented.

The production project identifier was previously rejected for public disclosure
by automatic approval review. It remains excluded. Deployment requires the
original private configuration through the authorized Sites workflow.

Example JSON/SQL files from the earlier export also had literal backslash-n
sequences. Those formatting errors are repaired. The private
`data/initial-employees.json` and `data/import-summary.json` remain excluded;
the local tests do not depend on them.

This change is limited to GitHub development/test support and documentation.
Production source, live deployment, environment variables, Supabase, RLS,
authentication and production records are not modified.
